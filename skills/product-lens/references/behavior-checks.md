# 行为检查清单

用于维护时设计独立行为测试，或在实际执行中核对输出。以下是预期，不是已经发生的验收；只验证文件格式不能证明这些行为。复测时保留真实输入、产物、动作和观察记录，模拟数据明确标记。

| 输入/情境 | 应有行为 | 禁止行为 |
|---|---|---|
| 用户只问skill能做什么 | 解释输入、五步产物、边界和用户参与 | 启动真实案例或部署 |
| 截图有中间缺页 | 逐张检查，标缺失过渡 | 凭教程拼完整成功路径 |
| 只有官方教程却要求试用 | 尝试定位真实入口，缺条件标阻断 | 输出文档旅程后称第一步完成 |
| AI连续操作产品 | 每个用户环节观察前后并定位证据 | 连点后从末页反推 |
| 客服反馈回复“已记录”却无回执 | 分开记录口头状态与业务状态 | 自动认定已解决或已转人工 |
| 用户要求完整第一步 | 真实观察、旅程后继续反推原产品职责/工具/数据/状态机制 | 只出体验总结；无证据猜后台实现 |
| 用户仅要第二步设计 | 先适配评估，再职责与工具/数据/工作流方案，最后生成PRD | 先写完整PRD再补适配理由；擅自开始开发 |
| 无实际Agent证据 | 模块职责和未知；候选设计另列 | 为填表生成多个官方Agent |
| 参考蓝图有mock MCP | 标模拟、真实接入待做 | 称工具服务已接通 |
| 真实模型不可用但mock通过 | 技术替身测试通过、真实效果待验 | 宣称业务闭环完成 |
| 产品只有IM渠道 | 验收会话/卡片，不强建网站 | 删除交互验收步骤 |
| 用户修改已确认输入 | 定位受影响产物，撤销过期确认 | 沿用旧版本验收 |
| 发布接口返回受理 | 查状态并验证线上真实任务 | 把请求成功当上线完成 |

协议脚本还需核对：空模板默认阻断、缺/旧/冲突引用阻断、文件内容变更阻断、用户未接受阻断、测试fixture默认拒绝。脚本不能判断观察真实性、用户意图或答案质量。
