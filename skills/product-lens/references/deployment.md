# 第五步：受控发布与实际使用验收

输入：已验收PRD、核心能力、正式交互、实际构建产物和目标环境。先核对现有资源与权限；用户只要方案时停止于P1，已授权发布则完成必要准备后执行，不为普通步骤重复确认。读[技术规则](engineering.md)。

| 阶段 | 工作 | 放行依据 |
|---|---|---|
| P0 | 核对代码、有效验收、首次/已有项目、资源现状 | 对象与受影响范围可定位 |
| P1 | 方案、费用、运行、身份、数据/文件、发布与回退 | 必要业务决定明确；技术现状已查 |
| P2 | 实际打包、启动/构建配置、必要资源 | 包内容与运行配置可复核；不含秘密 |
| P3 | 受控环境检查权限隔离、数据和恢复 | 真实用户使用前满足底线 |
| P4 | 发布指定产物、查询异步状态和实际版本 | 成败明确；不把提交发布当成功 |
| P5 | 线上逐层检验与真实用户任务 | 真实结果、入口、身份与所需设备符合AC |
| P6 | 如发生故障，定向修复或恢复 | 应用回滚与数据恢复分开；复验受影响链路 |
| P7 | 交接入口、操作、运维、限制和恢复方式 | 用户实际使用检查H6；状态明确 |

检查层：产物/运行配置、入口/通信、身份隔离、数据恢复、文件资产、模型/业务任务、日志与运营。网址可达、发布成功、真实业务通过、用户验收、恢复演练分别记录；未演练不宣称通过。

临时盘和预留实例都不等于持久存储。按目标确定可接受丢失窗口和恢复时间；数据库迁移须验证schema、数据完整性、并发与回退，不能只改连接字符串。云权限最小必要，不复制历史FullAccess配置；现有资源归属先查，不因失败反复新建。恢复未知的发布先查状态，不盲目重发。

仅使用受控凭据入口，禁止明文交付AK/SK、密码或可登录的邀请码。部署平台、费用、账号能力与政策实际执行前查当前官方依据；技术模板不是现成授权或上线保证。

交付：真实入口和产物标识、配置/资源清单、运行与检查证据、用户可照做验收、恢复与遗留问题。真实环境缺失可交付方案和待办，不能称上线完成。
