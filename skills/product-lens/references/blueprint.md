# 参考能力目录：逐项评估适配

s01–s17是本方法使用的参考能力索引，不是行业统一编号，也不代表原产品或某个框架已经实现。以当前用户提供或指定的蓝图/源码为依据建立映射；没有源码时只给能力层方案，不能宣称已核对某个参考实现。

先依据拆解和目标判断适配，再用本表检查实现方案。每项记录：目标/用户环节、采用/条件采用/不采用/待确认、理由、没有它的影响、简单替代、实际覆盖、接入缺口、参考来源与验证方式。

| ID | 能力 | 适配条件 | 必须核对的边界 |
|---|---|---|---|
| s01 | Agent Loop | 模型需要依据工具结果继续判断 | 无工具调用或模型结束不等于业务完成；固定流程可不需要自主循环 |
| s02 | 工具系统 | 调用外部或业务能力 | 实际接口、参数、结果、权限和调用者，不能只确认有分发表 |
| s03 | 权限 | 有受限数据或写操作 | 服务端权限、租户与资源范围，界面确认不代替鉴权 |
| s04 | Hooks | 有调用前后策略或审计需求 | 扩展点是否真实挂载；存在hook不证明已有安全或计费实现 |
| s05 | Todo | 需要当前会话可见轻量进度 | 内存清单不等于可恢复业务任务 |
| s06 | Subagent | 独立子任务需要上下文隔离 | 独立职责、输入、边界、回传与实际运行条件 |
| s07 | Skill Loading | 领域规则较多，适合按需加载 | 规则加载不等于RAG、资产库或业务权限 |
| s08 | Context Compact | 长会话或大输出导致上下文压力 | 保留原始证据、确认、回执和版本，不能只留摘要 |
| s09 | Memory | 明确需要跨会话偏好或决策复用 | 当前项目数据与长期用户信息分开，不默认存个人画像 |
| s10 | Task System | 多任务依赖或需要续作 | 持久化、并发认领与恢复是否真实存在 |
| s11 | Background Tasks | 慢操作需要后台执行 | 真正异步执行、任务身份、查询与取消；事件名不能证明队列存在 |
| s12 | Scheduler | 用户有明确定时或周期需求 | 进程退出、漏跑、重复触发和业务幂等 |
| s13 | Agent Teams | 独立任务并行收益高于协调成本 | 多个角色名称不证明多运行时；检查协作与隔离 |
| s14 | MCP | 实际外部能力通过MCP提供 | 传输、鉴权、真实服务；mock不算接入，HTTP不强制改MCP |
| s15 | Integrated Harness | 多机制确有统一调度需求 | 只组合需要的能力，不默认整套复制参考框架 |
| s16 | Workflow Runtime | 步骤、确认点与依赖明确 | 状态、恢复、schema、幂等；外部成功而本地未记账的窗口需处理 |
| s17 | Goal Loop | 需要汇总验收证据决定继续或停止 | 判断器只能消费它实际能获得的证据；结果校验需真实执行 |

源码复核表：`参考URL或文件→提交/版本→读取范围→观察到的实现→与文档声明差异→适配缺口→实际运行检查`。无法访问时保留未知，不能沿用过去某个项目的函数名和行号作为当前事实。

完整比对意味着每个组件有决策，不意味着采用全部组件。纯确定性完成条件由代码检查，即使不选s17也不能省略。只有当前项目状态时不引入长期记忆；无定时需求不引入scheduler；多轮对话不自动需要Agent团队。
